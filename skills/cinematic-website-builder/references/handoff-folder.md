# The hand-off folder (single source of truth)

```
handoff/
  brief.md            G0  facts, "The website will…" highlight, references, gate flags (front matter)
  moodboard.yaml      G2  approved references + motion phrases + custom-type style numbers
  design-spec.md      G5  tokens, type, spacing, grid, motion score, media, SEO/AEO, budgets, no-design pages, decisions log
  page-text.md        G5  every word, page by page, section by section
  wireframe.yaml      G4  pages × sections (kinds, headings, media, jumbo word); templates via use/each
  motion-plan.yaml    G3  generated by motion-pick.mjs (enforced by verify --motion-plan)
  type-inputs.yaml    G3  sector, dials, brand/reference fonts, real copy, custom_type_refs
  type/               G3  type-pick.yaml, type-tokens.css, specimens/, type-review.png, ai-letters.yaml, letter-review.html
  greybox/            G4  <slug>.html + <slug>-1440.png + <slug>-390.png, contact-sheet.png, sections.md, index.json
  sections/           G5  approved reference PNG per section: <pageSlug>--<sectionId>.png (bare <sectionId>.png for the home page)
  sitemap.xml         G1  from the SEO/AEO blueprint (greybox --sitemap cross-checks it)
```

Rules
- One spec. `design-spec.md` absorbs the old direction-brief synthesis and build-manifest. If two documents
  disagree, the spec wins and the decision goes in its §11 log.
- Build prompts (`build-chain.md`) read only from this folder. Nothing gets invented mid-build.
- Templates: `templates/handoff/`. Worked example: `references/examples/astonishing/`.
- verify's section diff compares rendered sections with `handoff/sections/*.png` (`--sections handoff/sections`,
  threshold 0.12). Use it when the PNGs are real design frames; skip it for greybox-only builds.
