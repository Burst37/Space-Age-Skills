## 3.5.0 — 2026-11-16
Goal: go from a Google Maps lead list to several verified cinematic spec sites a day across multiple harnesses, with
current image/video models and exact video prompts, without dropping steps the earlier skills had.
- **Lead mode** (`references/lead-pipeline.md`): L0 scrape → L1 score → L2 queue → L3 build → L4 preview → L5 batch
  review (the one human stop) → L6 pitch → L7 convert → L8 log. **`scripts/lead-jobs.mjs`**: `score` (column aliases
  for GeoFusion/GoSom/scraper-kit/sheet rows, dedupe, site status none / social-only / free-builder / dead / weak /
  decent, optional static `--audit`, priority with evidence lines), `init` (one job folder per lead from
  `templates/lead/`: prefilled brief, one-page wireframe, type inputs, `JOB.md`), `claim` (atomic), `done` (refuses
  without a passing verify report, `noindex`, the preview notice, or with an unfilled/UNKNOWN fact), `fail`,
  `release`, `status`. Maps categories map to the pickers' sectors and to real schema.org types only.
- **Multi-harness** (`references/multi-harness.md`): job-folder contract, one-line worker start, shared-disk claim vs
  one-job-per-isolated-session, frontier vs bulk lanes, parallel-run hygiene.
- **Live model roster** (`references/model-roster.md`): no model name is fixed in the skill any more. Roles (anchor
  still, hero loop, section clip, narrative, identity, finish) are matched against the roster read that day; client
  mode asks when the pick changed; picks and `roster_checked` are recorded per slot. `taste-profile.yaml → models`.
  Snapshot of 2026-11-16 included as evidence (the docs said GPT Image 2.5; the roster already had 2.6, Nano Banana
  2.1, FLUX 3, Kling 4.0 …).
- **JSON video prompting** (`references/video-json-prompting.md`, **`scripts/shot-lint.mjs`**, example in
  `templates/handoff/assets/shots/`): one JSON shot spec per clip, every cinematography field mapped to a section of
  **`space-age-cinematic-director` v4.1**; lint rejects multiple camera moves, missing path/invariants, non-matching
  loop frames, stale roster, token soup; `--compile` prints prose in the director's order.
- **Prompt contract rewritten** (`asset-pipeline.md` §3): direction from the director skill, tiered meta tokens (≤ 5,
  tier C opt-in), house camera per its root rule. The "≥ 150 words + 3–5 meta tokens" rule is retired.
  The consolidated director v4.1 file is added to `skills/space-age-cinematic-director-v3/references/`.
- **Steps restored after auditing the original skill and v3.2 against v3.4** (`references/pipeline-coverage.md`):
  beat sheet (Hook → Problem → Proof → Offer → CTA) in G5; **G11 voice**; **G12 outreach + log**;
  `ui-ux-designer` / `ui-ux-pro-max` as moodboard owner when Muse is absent. Five owners v3.4 routes to are in
  neither repo; stand-ins listed.
- **Portable AEO gate**: `verify.mjs` no longer hard-fails when `seo-aeo-optimizer` is not installed; it runs the
  same four blocking checks itself (raw-HTML content, Organization/LocalBusiness JSON-LD, H1, retrieval bots not
  blocked) and flags that no score was produced.
- **Regression self-contained**: fixtures the export could not carry (subject cut-out, favicons, letter-check PNGs)
  are generated by `tests/make-assets.mjs`; `run-all.sh` no longer assumes box paths. New checks: lead-jobs,
  shot-lint positive + negative, AEO built-in negative (shell page, blocked bots).
- **`SKILL.md` is now the router** (mode → what to read → which script gates it) instead of a stub that says "read
  everything".
- **Voice is Gemini Live only.** `voice-agent` (#38) is vendor-free; **`voice-gemini` (#43)** is the Gemini Live adapter with `templates/api/voice-token.mjs`. No third-party voice SDK, key or routing remains.

## 3.4.0 — 2026-11-15
Goal: add Google's Elephant-Goldfish Model (EGM, Apache-2.0, `google/elephant-goldfish-model` @ e4747323) as a lean review process.
- **Goldfish reviews at three points**, folded into existing gates: **GR1** after the G1 blueprint (brief), **GR2** after G5 (design-spec,
  page-text, motion plan, wireframe), **GR3** after G8 (drift: built preview vs spec). Fresh-context reviewers get only the doc, the CWB
  rule files and the sources; the elephant decides fix / contest / ask / accept-risk; `ask` items ride with the next approval Chuma
  already gives. Max 2 rounds; round 2 only when a blocker was fixed. Factory tier runs 2 lenses at GR1/GR2 and skips GR3.
- **`references/goldfish-review.md`** (protocol, roles, no-subagent fallback = labelled self-check) and **`references/goldfish-lenses.yaml`**
  (9 website lenses adapted from EGM personas: naive-client, conversion, search-and-answers, trust-and-tone, accessibility,
  motion-and-performance, brand-and-type, zoom-out, drift).
- **`scripts/goldfish.mjs`**: `pack` builds one packet per lens (PROMPT.md, target/, rules/, sources/ incl. saved URLs) and refuses
  transcript/notes/memory-like inputs; `lint` checks the merged report (status table, severity blocker/should/nit, scope, evidence,
  decisions with `--resolved`; a lens that did not run fails the round).
- Brief template front matter: `review_gr1`, `review_gr2`, `review_gr3`. Hand-off folder: `handoff/reviews/`.
- **Worked example revised** after a real GR1/GR2 run: `references/examples/astonishing/reviews/`, revised `brief.md` and `design-spec.md`,
  and **`EVAL.md`**: baseline 3.3 doc gates raised 1 issue; goldfish raised 20, 14 confirmed (3 blockers), 3 false positives,
  2 judgment; 13 confirmed issues were new. Verdict there: modest-to-significant at the doc gates, not "huge" overall; re-measure on
  the next two real builds.
- **Tests**: `goldfish-pack`, `goldfish-pack-refuses-notes` (negative), `goldfish-lint-example` (resolved worked example),
  `goldfish-lint-negative` (missing evidence + lens not run). 14 checks.
- Removed nothing. Backup of 3.3.0: `/workspace/backups/cwb-3.3.0/`.

## 3.2.0 — 2026-11-10
- **SEO + AEO wired into every build** via `seo-aeo-optimizer` (referenced, not copied). Protocol: `references/seo-aeo-gate.md`. Gate order is brief → Top-3 Competitor Teardown (`teardown.py --aeo`) → SEO/AEO blueprint (sitemap, page types, schema, answer capsules, entity/NAP) → Muse moodboard approval → code → SEO/AEO QA → ship.
- **`scripts/verify.mjs`** runs `seo-aeo-optimizer/scripts/aeo-check.py` on the local preview (or `--aeo-url`) via async spawn so the in-process server can answer. Blocking: content missing from raw HTML, no Organization/LocalBusiness schema, no H1, retrieval AI bots blocked. `--skip-aeo` is for the runtime gallery only. Set `SEO_AEO_SKILL` if the owner skill is not a sibling.
- **Build-time cinematic/GSAP rules:** copy, headings and JSON-LD in the initial HTML; animations never hide content from crawlers; no text only in canvas/WebGL; reduced-motion fallback; CWV budgets (LCP < 2.5s, INP < 200ms, CLS < 0.1); lazy-loaded heavy assets; posters on video; question-shaped H2s with 40–60 word answers on service pages; LocalBusiness/Service schema; `templates/robots.txt` (retrieval bots allowed), optional `templates/llms.txt`, `templates/sitemap.xml`, IndexNow on ship.
- **Industry ban** restated as a hard rule: no liquid-glass or 3D goo typography on law, SaaS, medical or home-healthcare sites.
- **Agent Reach integrated** as the P0 design / voice-of-customer research layer (`references/web-research-agent-reach.md`). Ranking-competitor teardown stays with `seo-aeo-optimizer`. Ponytail + caveman listed as always-on code and token discipline. (Drafted 2026-10-15 in the skills repo; landed here with 3.2.0.)
